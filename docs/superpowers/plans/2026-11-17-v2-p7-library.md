# v2 P7 — Library Screen (with its Inspector) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or
> superpowers:executing-plans. Tasks state interfaces, tests and done criteria (owner's global
> CLAUDE.md §6); they do not script every line.

**Goal:** The Library screen and its Inspector, composed from primitives on the P6 foundation and
measured against the design contract in two states (`library`, `library+inspector`), **with
positions**. Static composition: the screen takes typed props and emits intents; wiring to `/v1`
is P6b (Tasks 6.6–6.8 of the foundation plan).

**Architecture:** [v2 spec](../specs/2026-11-16-v2-architecture-design.md) §9–§10,
[ADR-0023](../../decisions/ADR-0023-one-visual-authority-and-a-contract-gate.md). Foundation:
[`2026-11-16-v2-p6-web-foundation.md`](2026-11-16-v2-p6-web-foundation.md). Parent plan:
[`2026-11-16-v2-rewrite.md`](2026-11-16-v2-rewrite.md) (global constraints apply). Behaviour owners:
[`UI-SPEC.md`](../../UI-SPEC.md) §0.4, §2, §13; [`FEATURES.md`](../../design/FEATURES.md) §1–§2;
[`DESIGN-GUIDELINES.md`](../../DESIGN-GUIDELINES.md) §7, §9;
[ADR-0009](../../decisions/ADR-0009-responsive-ladder.md),
[ADR-0010](../../decisions/ADR-0010-one-staging-tray.md). Entity shapes:
[`ENGINE-API.md`](../../ENGINE-API.md) §3, §8.1.

**Rules this plan holds itself to** (spec §9.2, and the review's U3–U7, R2, R3):

- Visual CSS lives in `web/src/ui` only. `features/` and `screens/` carry layout (display, grid,
  gap, padding, overflow) and nothing else; a look a feature needs becomes a primitive.
- Nothing here fetches or keeps a private copy of server data: every value shown is derived from
  props (U3, U7, R2). No "undo last" — undo addresses an op id the mutation returns (U4, Task 6.7).
- One keymap: `Space`, `F` and `Delete` are global-scope bindings, so an open overlay's blocking
  scope stops them (U5). The grid is one tab stop (U6).
- Tokens only. A fixed box size the vocabulary cannot collect (it has no width/height category)
  is a named metric in the `app-only` block of `tokens.css`, as the frame metrics already are.

### Task 7.3: Asset actions, selection, grid math

**Files:** Create `web/src/features/asset/actions.ts`, `web/src/state/selection.svelte.ts`,
`web/src/features/asset/grid.ts`; tests beside each. Modify `web/src/app/keymap.svelte.ts`
(export `isControl`).

- `actions.ts` is the only place an asset intent is defined. `AssetIntent` is branded with a
  module-private symbol, so no other module can construct one. Exports: `ACTIONS` (id → label,
  icon, shortcut, `unavailable(ctx)` reason, `intent(ctx)`), `intentFor(id, ctx)`,
  `menuFor(ctx): MenuEntry[]` (DESIGN-GUIDELINES §7 order: Open, Quick Look, Reveal, Open with
  default app, Copy name, Copy path, Favorite, Stage, Import…, Export to folder…, Add to
  collection…, Edit tags…, Re-identify, Find similar, Move to Trash), and
  `bindAssetKeys(keymap, source, emit)` — `Space` Quick Look (lead), `F` favourite (pick set, else
  lead), `Delete` trash (lead only, UI-SPEC §0.4), `Escape` clears picks then the lead.
  `ctx = { targets, project }`; project-bound actions are unavailable with a reason when no project
  is active.
- `Selection`: `lead` (what the inspector describes), `picks` (what bulk actions act on), a Shift
  anchor. `open(id)` (click: toggles the lead), `moveTo(id)`, `toggle(id)`, `extendTo(id, order)`,
  `pickAll(order)`, `clear()`, `prune(order)`, `targets(id?)` — a card outside the pick set is its
  own target; inside it, the whole set is.
- `grid.ts` (pure): `columnsFor(width, minCard, gap)`, `moveIndex(index, key, columns, count)`,
  `rowsOf(items, columns)`.
- [ ] Vitest: the intent a key, a menu item and a direct call produce for one action are equal; a
  disabled action yields no intent and carries its reason; `Space`/`F`/`Delete` do not fire under a
  blocking scope and `Space` does not fire on a focused `<button>`; a source scan finds no
  `AssetIntent` constructed or cast outside `actions.ts`; selection rules above; column math at the
  three densities (1197 px → 7 / 5 / 3)
- [ ] Commit `feat(web): asset actions, selection and grid math`

### Task 7.5: AssetCard and AssetGrid

**Files:** Create `web/src/features/asset/AssetCard.svelte`, `AssetGrid.svelte`; tests
`AssetGrid.test.ts`, `AssetCard.test.ts`.

- `AssetCard`: props `asset`, `selected`, `picked`, `picking`, `tabStop`, `project`, `traits`,
  `thresholds`; events `onopen(event)`, `onpick`, `onaction(id)`, `onmenu(event | element)`,
  `ontag(value)`. Composition and wiring only.
- `AssetGrid`: `role="grid"` → `role="row"` (`display: contents`) → cards. **One tab stop**: exactly
  one card has `tabindex="0"` (the lead, else the last focused, else the first); every control
  inside every card has `tabindex="-1"`. Keys on the grid: arrows / Home / End move the lead and
  focus follows it (Shift extends the pick set); Enter opens; Space quick-looks the focused card;
  Ctrl/Cmd-A picks the page; Menu key or Shift+F10 opens the context menu at the card.
  **Inner-button focus pattern (the one pattern):** `F2` moves focus from a card to its first
  control; inside, ←/→ (and ↑/↓) move among that card's controls, Home/End jump to its ends,
  `Escape` or `F2` returns to the card; Tab always leaves the grid. This is the APG grid pattern's
  "cell that contains widgets". Every control's action is also a key or a context-menu item.
- Columns: a `ResizeObserver` gives the width; `columnsFor` turns it into a count with the density's
  min-width and the gap, each read once from the grid's custom properties when the density changes —
  never a computed-style query per keypress or per card. `columns` can be given (tests; a one-column
  list). The grid renders one page (UI-SPEC §2 pagination), so it is not virtualised; rows are the
  unit a windowing pass would use if a page size ever needs one.
- [ ] Vitest: one element with `tabindex="0"` in the grid, none inside cards; arrows move focus and
  the lead by one and by a row; Shift+arrow extends picks; F2 / arrows / Escape follow the pattern
  and no inner control ever becomes a tab stop; a card's buttons emit the same intents as
  `actions.ts`; clicking a button inside a card does not open it
- [ ] Commit `feat(web): asset card and grid — one tab stop, roving focus`
