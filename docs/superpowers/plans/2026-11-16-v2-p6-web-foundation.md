# v2 P6 — Web Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or
> superpowers:executing-plans. Tasks state interfaces, tests and done criteria (owner's global
> CLAUDE.md §6); they do not script every line.

**Goal:** A `web/` Svelte 5 app whose tokens are derived from the prototype, whose primitives are
measured against the design contract, and whose data layer and shell talk to `/v1` — so every P7
screen is assembled from parts that already match the design.

**Architecture:** [v2 spec](../specs/2026-11-16-v2-architecture-design.md) §9–§10,
[ADR-0023](../../decisions/ADR-0023-one-visual-authority-and-a-contract-gate.md). Parent plan:
[`2026-11-16-v2-rewrite.md`](2026-11-16-v2-rewrite.md) (global constraints apply).

**Tech stack:** Svelte 5 (runes), Vite 6, TypeScript 5, Bun, Vitest (unit), playwright-core
(gate; Edge channel by default, `LS_BROWSER_CHANNEL=""` for bundled Chromium).

**What already exists (do not rebuild):** `scripts/design/extract-contract.mjs` (+ `lib/measure.mjs`,
`lib/prototype.mjs`, `states.mjs`, `anchors.mjs`) writes `docs/design/contract.json` and
`docs/design/vocabulary.json`; `--check` verifies them. `measureInPage({ anchor })` already
measures an app element marked `data-anchor`.

Split: **P6a** (Tasks 6.1–6.5) needs no backend and can run beside P3. **P6b** (Tasks 6.6–6.8)
needs P3's server.

## P6a

### Task 6.1: Tokens derived from the prototype, and the check that keeps them so

**Files:** Modify `docs/design/tokens.css`; create `scripts/design/check-tokens.mjs`; modify
`docs/DESIGN-GUIDELINES.md` §2–§4, §8 (prose must match the file); `package.json` script
`design:tokens`.

**Rules the check enforces** (exit 1 on any violation):

1. Every value in `vocabulary.json` → `color`, `background`, `border` (colour part), `gradient`,
   `fontSize`, `fontWeight`, `fontFamily`, `letterSpacing`, `radius`, `gap`, every component of
   `padding`, `shadow`, `duration`, and every colour/shadow/length inside `hover` has a token in
   `tokens.css` with exactly that value (normalise colours to lowercase `#rrggbb[aa]`, lengths to
   px, durations to ms). `99px` radius counts as `--r-pill` (renders identically below 198 px).
2. Every token in those families is either used by the vocabulary or sits inside a block marked
   `/* app-only: <reason> */ … /* end app-only */` (focus ring, z-layers, control heights,
   breakpoints) or `/* legacy: removed at P5 */ … /* end legacy */` (names the old `ui/` still
   imports — `tokens.css` is imported by `crates/lodestash-desktop/ui/src/styles/app.css` until P5,
   so **existing token names must keep resolving**).

**Naming:** keep the existing semantic colour names (`--ls-bg`, `--ls-surface`, `--ls-gold`, …);
alpha variants `--ls-<name>-a<percent>` (e.g. `--ls-gold-a15` = `#e7b76526`); numeric scales where
the prototype has no semantic ladder — `--fs-<px>`, `--sp-<px>`, `--r-<px>`, `--r-pill`,
`--dur-<ms>`; shadows `--glow-<color>-<blur>` / `--ring-<color>-<width>`; gradients
`--grad-<name>`; families `--ff-display|ui|mono`. One-off values are named, not snapped
(ADR-0023 §2).

- [x] Test: `node scripts/design/check-tokens.mjs` passes on the new file, and fails (exit 1, naming
  the value) when one vocabulary colour is removed from `tokens.css` — prove with a temp copy
- [x] The old UI still builds: `bun run --cwd crates/lodestash-desktop/ui check` is green
- [x] Commit `feat(design): tokens name every value the prototype draws`

### Task 6.2: `web/` scaffold, fonts, icons, style lint

**Files:** Create `web/{package.json,vite.config.ts,tsconfig.json,svelte.config.js,index.html,gallery.html}`,
`web/src/{main.ts,styles/{reset.css,layers.css,app.css}}`, `web/public/fonts/*` (copy the three TTFs and

`docs/TECH-STACK.md` (Vitest).

- `web/src/styles/app.css` imports `docs/design/tokens.css` (one source; same mechanism the old UI
  uses). Fonts load from `/fonts/*.ttf`; no remote font, ever (CSP-equivalent: the dev server sets
  `Content-Security-Policy` without remote font sources).
- Icons: the sprite is single-sourced from `docs/design/icons/icons.svg`, served/emitted by a small
  Vite plugin as `/icons.svg`; `web/src/ui/icons.generated.ts` exports the id union, generated by
  `scripts/design/gen-icons.mjs` (with `--check`). Icons use `currentColor`; where the sprite bakes
  a hex stroke, the generator rewrites it to `currentColor` in the emitted file (the source stays
  as the designer exported it).
- The prototype draws nav and action glyphs as Unicode characters; the app uses the designed SVG
  set (ADR-0012) at the glyph's measured box. Add that row to `docs/design/DEVIATIONS.md`
  (anchors `sidebar.nav.icon`-type glyphs, property: glyph shape only — box, colour and spacing are
  still checked).
- `check-styles.mjs`: in `web/src/**/*.{svelte,css}` except `docs/design/tokens.css`, reject colour
  literals (`#…`, `rgb(`, `hsl(`), lengths other than `0`, `1px`, `100%`, `fr` units, numeric
  `z-index`, literal `transition`/`animation` durations, literal `box-shadow`, `opacity` other than
  `0`/`1`. Each finding prints `file:line`. Exit 1 on any.

### Task 6.3: Primitives

**Files:** `web/src/ui/*.svelte` (+ `web/src/ui/index.ts`), unit tests `web/src/ui/*.test.ts`.

The primitive list is spec §9.3. Rules (spec §9.2): real `<button>`/`<input>`/`<a>`; visual CSS
only here; tokens only; props typed; no API calls.

- `Dialog`: renders into the overlay host; scrim; Escape closes; focus moves in on open, is trapped
  (Tab and Shift-Tab cycle), and returns to the opener on close; the app root gets `inert` while
  open. `ConfirmDialog` builds on it (destructive variant: the safe action is the default button).
- `Menu`/`ContextMenu`: positioned by measuring its own size against the viewport (never a hard-coded
  height); arrow keys move, Enter activates, Escape closes and restores focus.
- `keymap.svelte.ts` (in `web/src/app/`): a scope stack; `Dialog`/`Menu` push a scope while open, so a
  global shortcut never fires behind them.
- [x] Vitest (with `@testing-library/svelte` or plain DOM — choose and add to TECH-STACK): focus trap
  cycles; focus restored to opener; Escape closes the top-most overlay only; a global shortcut
  does not fire while a Dialog is open; Menu flips upward when it would overflow the bottom
- [x] Commit `feat(web): primitives — buttons, chips, fields, dialog, menu, keymap scopes`

*As built:* plain DOM — Svelte's `mount`/`flushSync` on `jsdom` (TECH-STACK §5); geometry is
stubbed in tests, the gate owns real layout. Beyond §9.3 the library has the frame's chrome as
primitives (`AppBar`, `Rail`, `RailHeading`, `Divider`, `Wordmark`) so features carry layout only,
and the composites the gallery needs (`StatusGem`, `SizeTier`, `TraitChip`). `Tooltip` is an
attachment, `{@attach tooltip(text)}`. The overlay host and modal stack are `web/src/app/overlay.ts`.
Icons take a drawn `size` and a layout `box`, so an icon keeps the measured advance of the Unicode
glyph it replaces (DEVIATIONS row 1). **Line height is not the fonts' `normal`:** the prototype's
root sets `line-height: 1.45` and every contract height (13 px → 18.9, 12 px → 17.4) is measured
with it, so `--lh-body` moved out of the legacy block and `body` sets it. The focus ring is the
global `:focus-visible` rule, `!important` so a primitive's own shadow cannot hide it. Three sprite
symbols sat after `</svg>` (invalid XML — no icon could load); they moved inside `<defs>`.
`check-styles.mjs` now reads multi-line values (a `transition:` list was never linted).

### Task 6.4: Gallery and the primitive-level gate

**Files:** `web/src/gallery/Gallery.svelte` (entry `web/gallery.html`); `scripts/design/lib/compare.mjs`;
`web/e2e/gate.mjs`, `web/e2e/lib/report.mjs`.

- The gallery renders a **specimen** for every contract anchor a primitive can reproduce on its own
  (e.g. `topbar.mode` + `.on`/`.off`, `topbar.category`/`.on`, `topbar.project`, `topbar.hardware`,
  `sidebar.nav`/`.on`, `sidebar.nav.badge`, `sidebar.facet`, `sidebar.addSource`,
  `library.sort`, `library.favorites`, `library.filters`, `library.density`/`.on`, `card.chip`,
  `card.chip.lead`, `card.chip.more`, `card.size`, `card.stage`, `card.favorite`, `card.status`),
  with the **same text content** the prototype shows, marked `data-anchor="<name>"`.
- `compare.mjs`: `compare(expected, actual, compareList, { ignore }) → Diff[]` implementing the
  property groups and tolerances documented at the top of `scripts/design/anchors.mjs`; reads
  `docs/design/DEVIATIONS.md` rows and exempts exactly the listed (state, anchor, property) triples.
  In gallery mode `pos` is skipped.
- `gate.mjs --gallery`: builds or serves the gallery, measures every specimen with
  `measureInPage({ anchor })`, compares to `contract.json` state `library`, prints a table, writes
  `test-reports/MM-DD-HH-MM.csv` (owner's convention: one row per check with origin
  `web/e2e/gate.mjs`, status, duration, detail), exits 1 on any diff. A check over 5 s fails.
- Known prototype artefact: `library.sort` measures `fontFamily: Arial` — the browser default for a
  `<select>` the prototype never styled, not a design choice. The app's select uses the UI font;
  record that one property in `DEVIATIONS.md` rather than copying Arial. Line heights are the
  fonts' `normal`; do not set `line-height` globally or every box height drifts.
- [ ] Test (`scripts/design/lib/compare.test.mjs`, run with `node --test`): ±1 px box tolerance;
  exact colour; a DEVIATIONS row exempts only its property
- [ ] `bun run web:gate -- --gallery` green
- [ ] Commit `feat(web): the gallery measures every primitive against the contract`

## P6b (after P3)

### Task 6.6: API client and generated types

`web/src/api/client.ts` (fetch; `credentials: 'same-origin'`; typed `ApiError` from the envelope;
`AbortSignal` on every call; reads `X-Lodestash-Gen`), `web/src/api/generated.ts` generated from
`protocol.schema.json` (generator + `--check`), `web/src/api/events.ts` (SSE with reconnect and
backoff), `web/src/api/media.ts` (URL builders for `/v1/assets/{id}/…`). No other module calls
`fetch` (lint rule in `check-styles.mjs`' sibling `check-imports.mjs`).

### Task 6.7: Resource cache and mutations

`web/src/data/query.svelte.ts`: key → `{ data, error, status, gen }`; dedupe in-flight; abort and
discard superseded responses; invalidate by tag on SSE `changed`; refetch only active resources.
`web/src/data/mutations.ts`: each mutation declares the tags it invalidates and returns the op id;
undo/redo address that id. Vitest covers: dedupe; a late response for an old key is discarded; an
SSE event refetches an active resource and not an inactive one; undo sends the returned op id.

### Task 6.8: Fixture catalog and the app gate

A Rust test helper (in `lodestash-engine`, `#[cfg(feature = "fixtures")]` or a small bin in
`crates/lodestash-desktop` behind `--build-fixture <dir>`) creates a catalog with the prototype's
19 assets, packs, libraries, statuses, tags and sizes, plus tiny generated media files.
`web/e2e/gate.mjs --app` starts `lodestash-desktop --serve` on that fixture with
`LODESTASH_CATALOG`/`LODESTASH_CONFIG_DIR` in a temp dir, opens the printed session URL, drives the
app into each contract state, and compares all anchors (with `pos`). Done when the shell (top bar,
sidebar with live counts from the fixture) passes against `contract.json` state `library`.
