# Lodestash v2 Rewrite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking. Per the owner's global CLAUDE.md §6, tasks state the
> interfaces, the tests that prove them and the done criteria; they do not script every line.
> Phases P5–P8 get their own detailed plan, written against the code as it stands after P4.

**Goal:** Restructure Lodestash into an app whose engine is the single owner of the catalog,
serving one derived `/v1` API to its own web UI and to a standalone thin-client MCP server, with
the UI held to the design by a measured contract.

**Architecture:** [v2 architecture spec](../specs/2026-11-16-v2-architecture-design.md). Keep
`lodestash-core`/`-ingest`/`-ai`; add `lodestash-protocol` (operation catalog) and
`lodestash-engine` (absorbs `lodestash-app` and the desktop writer/read model); reduce
`lodestash-api` to an adapter and `lodestash-desktop` to a window; rebuild the UI in `web/`.

**Tech stack:** Rust 1.96 stable (std file locks available), rusqlite 0.32 (bundled SQLite),
axum 0.8, rmcp 2.2, schemars 1, Tauri 2.11, Svelte 5, Vite 6, Playwright (Chromium), Bun.

## Global constraints

- Work on branch `rewrite/v2`. Commit per task; **never push**; never commit to `main`.
- Commit messages end with the session's `Co-Authored-By` trailer; append `[skip ci]`.
- Code follows the spec; a divergence updates the spec (or the owning doc) in the same commit
  (repo CLAUDE.md rule 2). New dependencies get a line in `docs/TECH-STACK.md` (rule 5).
- Invariants (repo CLAUDE.md): local-first, non-destructive, MCP↔REST 1:1 for agent operations,
  status lifecycle `discovered → indexed → identified → confirmed`, the seven-value `media_type`
  enum, `/v1` versioning, product name Lodestash, crates `lodestash-*`.
- Existing catalogs must keep opening. Migrations are additive and preceded by a backup.
- Tests never touch the user's catalog or config: use `tempfile` and `LODESTASH_CATALOG` /
  `LODESTASH_CONFIG_DIR`. A test that hangs past 5 s fails unless it declares a longer budget.
- Gates per task: `cargo test --workspace`, `cargo clippy --workspace --tests -- -D warnings`,
  `cargo fmt --all --check`; doc-touching tasks also `node scripts/check-docs.mjs`.

- **P5 Thin shell.** Single instance, `--serve`/`--background`, window at the session URL, engine

  `agent_bridge.rs` went in P4). Done when `lodestash-desktop` has no `#[tauri::command]` and the MCP

- **P6 Web foundation.** `scripts/design/extract-contract.mjs` → `docs/design/contract.json` and

  resource cache + mutations + SSE; generated client; Shell (top bar, sidebar, status); fixture
  catalog builder (`tests/fixtures/`); Playwright gate. Done when the shell passes the contract for
  the frame anchors (top bar, sidebar, nav rows, facets).

  behaviours from `UI-SPEC.md` have e2e checks on the fixture catalog, and `DEVIATIONS.md` explains
  every listed difference.
- **P8 Integrity and reconciliation.** Per-stage failure state (R8, B6/B7/B9/B3), pinned model
  hashes (B14), canonical delete fence (B15), SQL-backed read model, MCP streamable HTTP, and the
  rewrite of `ARCHITECTURE.md`, `ENGINE-API.md` §1, `UI-SPEC.md` shell sections, `HANDOFF.md`.
