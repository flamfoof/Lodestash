# Lodestash — Kanban

The working board for building Lodestash. Cards are grouped Backlog → Ready → In Progress → Review →
Done; **move a card across columns as you work it** (per the `CLAUDE.md` rule). Each card names the
design doc that governs it — read that doc before implementing, and update it if the implementation
diverges.

Card tags: **[P0]**–**[P7]** = roadmap phase ([`ROADMAP.md`](ROADMAP.md)) · **[spike]** = decision to
resolve first · **[QoL]** = cross-cutting browser-UX lane (M1.5), layered on Phase 1 ·
**[fable]**/**[opus]** = recommended model tier for the implementing agent — **fable** where the
hard part is judgment (cross-crate architecture, concurrency, migrations/data integrity, thin or
absent spec), **opus** where the spec already made the decisions (build-to-spec). Borderline cards
start on opus and escalate if they stall.

- [ ] **[P1]** **[fable]** 3D viewport + normalize→glTF cache (Assimp/FBX2glTF) — **spike resolved** ([`TECH-STACK.md`](TECH-STACK.md) §7): three-d 0.18 shares eframe's Glow context (`from_gl_context` + egui `PaintCallback`, glow-0.14 lockstep — upgrade the pair together). *Viewport slice shipped* (`viewport3d.rs`): Quick Look renders glTF/GLB/OBJ in an orbit viewport (left-drag orbit, right/middle-drag pan, scroll dolly, double-click reframe; auto-framed from mesh AABB; ambient + key + fill lights; background parse thread → UI-thread GPU upload, staleness-guarded, buffers freed on close; mirrors the image-viewer lifecycle). *FBX slice shipped* (`mesh.rs` via ufbx — see TECH-STACK §7): FBX flattens to world-space triangle soup feeding the same viewport, with **albedo textures** (embedded blobs, declared paths, or basename lookup against same-package extracted images; decoded through the shared `raster::decode` seam, ≤4k, bottom-up rows so raw FBX UVs sample correctly). *Parse-once mesh cache shipped (2026-07-26)* — the "normalize→glTF cache" from this card, built as a normalized **MeshData binary** (`mesh::load_cached` → `cache_dir/mesh/<key>.msh`, key = `(path,size,mtime)`), **not glTF**: internally only `MeshData` is consumed, so a direct binary skips a glTF-writer dependency **and** a parse-back round-trip; textures aren't cached (thumbnails/embeddings render untextured base-colour, and the textured Quick Look viewport keeps its own uncached `load_meshes` path). The win is cross-consumer: the metrics drain (every scan) parses each FBX for tri-count **through the cache**, so browse-time thumbnail generation reads it instead of re-parsing — which is what removes the browse CPU spike (parsing is the cost, not the raster; GPU wouldn't help — TECH-STACK §7). Manual binary format is bounds-checked (a corrupt/old entry silently re-parses); tested (encode/decode round-trip + cache-served-over-reparse, mutation-checked). *Embedding multiview wired (2026-07-26)* — `embed_model_multiview` loads through `load_cached` too, so identify reuses the geometry the scan/thumbnails already parsed. The **Quick Look viewport is deliberately left uncached**: it needs textures (the cache is geometry-only) and it opens one asset at a time on a user action, so it is not a spike — re-parsing one FBX for a deliberate open is fine, and reattaching textures to cached geometry would add complexity for no perf win. *Low-poly preview proxies shipped (2026-08-01)* — the parse-once cache made previews cheap to *load*; this makes them cheap to *render and store*. `lodestash_ingest::decimate` collapses `MeshData` onto a uniform voxel grid (binary-searching the grid resolution for the finest grid inside the budget, averaging each cell's members, dropping degenerate + duplicate triangles), and `mesh::load_preview_cached` caches the result as `cache_dir/mesh/<key>-<budget>.lod` on the same `(path,size,mtime)` key **plus a budget tag** — without the tag, raising on-screen quality would keep serving the coarse proxy for every cached model. It then deletes the staging `.msh`, which is where the disk win comes from (ceiling, `ponytail:`-noted: a re-scan re-parses the source). Budget is a **ratio clamped to a floor and ceiling** (`decimate::Budget`, wired to `PreviewQuality::proxy_budget()` — Low 2%/[300,1500], Medium 5%/[600,4000], High 12%/[1200,12000]) because a bare ratio leaves a 500k-tri hull heavy and erases a 400-tri prop, while a bare fixed count spends the same budget on both. Grid/list thumbnails (`thumb::render_model_thumb`) and the **multiview embedding** (`embed_model_multiview`) both render the proxy — SigLIP reads silhouette, which decimation preserves, and sharing the artifact keeps one cached mesh per file rather than two. **`metrics::triangle_count` deliberately stays on `load_cached`**: the `triangles` facet must be the source count, not the proxy's. Measured on a real 31,869-tri character: **1,026 tris, 3,361 KB → 38 KB of cache (88×)**, and the rendered proxy was eyeballed beside the full render — pose, silhouette, hair, skirt and weapon all intact. Verified: 7 unit tests (tri-count drop, AABB preserved within tolerance, no NaN/degenerate verts, index bounds, budget split across meshes, clamp at both ends), with **both** the target-count guard and the source clamp mutation-checked; `probe_proxy_render` is the ignored visual/footprint probe. *Remaining*: offscreen turntable pre-renders (next card)

- [~] **[P1]** **[opus]** Animated sprite/spritesheet playback; **material sphere** preview; **font** glyph-sheet — *material sphere shipped (2026-07-23)*: 207 materials stopped being flat `MAT` placeholders. `lodestash_ingest::material` builds a UV sphere and renders it through the **existing** CPU rasteriser (`render3d`), so there is no second renderer and no GPU context — the same reason model thumbnails work on worker threads. The texture comes from the **dependency graph**: `Catalog::material_albedo_paths` turns each material's resolved `uses_texture` edge into a file path, which is the first thing P2's graph pays for outside export.
